# TaleemMate — Architecture

AI-powered tutoring mobile app (Flutter / Dart 3.10). Supports English and Urdu. Targets iOS and Android.

---

## Startup Sequence

```
main()
  └─ AppFlavor.init()          # detect flavor + device ID
  └─ runApp(TaleemMate())

TaleemMate (StatefulWidget)
  └─ MultiProvider
       ├─ AppProvider           # theme + firstOpen (reads SharedPreferences)
       └─ [bloc-initiate-*]     # cubits injected here by hygen templates
  └─ Consumer<AppProvider>
  └─ MaterialApp
       ├─ theme / darkTheme     # materialLightTheme / materialDarkTheme
       ├─ initialRoute: /splash
       ├─ routes: appRoutes     # static map (/login, /create-account, /splash)
       ├─ onGenerateRoute       # FadeRoute for main nav screens
       └─ navigatorObservers: [RouteLogger]
```

## Screen Anatomy

Each screen is a self-contained directory of `part` files:

```
lib/ui/screens/<name>/
├── <name>.dart          # Root — StatelessWidget, ChangeNotifierProvider<_ScreenState>
├── _state.dart          # _ScreenState extends ChangeNotifier (ephemeral UI state + formKey)
├── static/              # Only present if screen has a form
│   ├── _form_keys.dart  # String constants for FormBuilder field names
│   └── _form_data.dart  # Debug prefill values (kDebugMode guard)
├── widgets/             # Sub-widgets as part files (_body.dart, _header.dart, etc.)
└── listeners/           # BlocConsumer / BlocListener wrappers
```

**Root pattern:**

```dart
class FooScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    App.init(context);                        // must be first in every build()
    return ChangeNotifierProvider<_ScreenState>(
      create: (_) => _ScreenState(),
      child: const _Body(),
    );
  }
}
```

The `Screen` widget (master scaffold) wraps the content and handles:
- `FormBuilder` injection when `formKey` is provided
- `FocusHandler` keyboard dismissal when `keyboardHandler: true`
- `PopScope` back-press interception
- Bottom bar visibility for the five main nav routes
- `overlayBuilders` / `belowBuilders` slots for listeners and modals

## State Management

Two layers coexist — they have different jobs and never mix.

### Layer 1 — Provider (ephemeral UI state)

`_ScreenState extends ChangeNotifier` lives inside a screen and holds only local UI state: form key, toggle flags, animation booleans. It never touches business logic or data.

```dart
final state = _ScreenState.s(context);         // read-only, no rebuild
final state = _ScreenState.s(context, true);   // rebuild on change
```

`AppProvider` (app root) persists theme choice and `firstOpen` flag.

### Layer 2 — BLoC / Cubits (business logic)

Cubits are registered in `TaleemMate`'s `MultiProvider` block. Every async operation is represented by a `BlocState<T>` field inside the cubit's state.

**State lifecycle:**

```
def → init → preparing → loading → success
                                  → failed
                                  → cancelled
```

**BlocState API:**

```dart
// Transitions (each returns a new immutable state)
state.someField.toLoading()
state.someField.toSuccess(data: result)
state.someField.toFailed(fault: fault)
state.someField.toCancelled()

// Boolean checks (via BlocActionMixin)
state.someField.isLoading
state.someField.isSuccess
state.someField.isFailed
state.someField.isDefault

// Functional style
state.someField.when(loading: ..., success: ..., failed: ..., orElse: ...)
state.someField.maybeWhen(loading: ..., success: ..., orElse: () => ...)
```

## Fault Hierarchy

`Fault<T>` is a sealed class. All error handling uses subtypes — never raw exceptions.

```
Fault (sealed)
├── HttpFault           — DioException → parses response body + status code
├── FirebaseAuthFault   — FirebaseAuthException → human-readable auth messages
├── FirebaseFault       — FirebaseException → maps known error codes
├── ExceptionFault      — generic Dart Exception
├── ErrorFault          — Dart Error
├── NetworkFault        — connectivity failures
├── UnknownFault        — catch-all string
└── CustomFault<T>      — typed domain-specific error data
```

Access the user-facing string from any subtype via the `FaultExtension`:

```dart
fault.message
```

Construct from a caught object:

```dart
Fault.fromObjectAndStackTrace(object, stackTrace)
```

## Form System

Forms use `flutter_form_builder` + `form_builder_validators` with custom wrappers. Every form screen provides:

- `_FormKeys` — static string constants (field names)
- `_FormData.initialValues()` — debug-mode prefill values
- `formKey = GlobalKey<FormBuilderState>()` in `_ScreenState`
- `Screen(formKey: ..., initialFormValue: ...)` — injects `FormBuilder` automatically

**Custom input widgets** (all backed by `FormBuilderField` + `AppFormBase`):

| Widget | Purpose |
|---|---|
| `AppFormTextInput` | Text, email, password, numeric, multiline |
| `AppFormDateInput` | Date picker with `intl` formatting |
| `AppFormChipsInput` | Multi-select chip list |

`AppFormBase` provides consistent label, border animation, error display, prefix/suffix icons, and `AppFormState` styling across all inputs.

## Design System

All tokens are in `lib/configs/` and available through the `configs.dart` barrel import.

| Token | Access |
|---|---|
| Colors (theme-aware) | `AppTheme.c.primary` `.accent` `.text` `.subText` `.background` `.subBackground` |
| Colors (static) | `AppColors.primary` `.accent` `.error` `.success` `.warning` |
| Typography | `AppText.b1` / `AppText.b2` — chainable `.cl(color)` `.w(weight)` `.gm()` |
| Spacing widgets | `Space.y.t08` `Space.x.t04` `Space.a.t12` `Space.h.t04` `Space.t.t08` |
| Spacing values | `SpaceToken.t04` … `SpaceToken.t64` |
| Border radius | `12.radius()` → `BorderRadius.circular(12)` |
| Icons | `LucideIcons.*` (`flutter_lucide`) |
| Fonts | Geist (body), Fraunces (display), GeistMono, NotoNastaliqUrdu |
| Animation durations | `AppProps.medium`, `100.milliseconds` (supercharged extension) |

`App.init(context)` must be called at the top of every `build()` — it bootstraps theme, media query, spacing, and typography for the current frame.

## Scaffolding (hygen)

Screens and their boilerplate are never written by hand:

```bash
hygen screen new <name>              # screen + state + optional form + widgets + routes
hygen screen consumer <name>         # BlocConsumer listener (loading overlay + flash messages)
hygen screen listener <name>         # BlocListener (flash messages only, no overlay)
hygen screen _widget <widget_name>   # add a widget part file to an existing screen
```

`router.dart` and `routes.dart` are patched automatically on `new`.
